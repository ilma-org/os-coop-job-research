Processes, threads, scheduling & The Linux scheduler selects which runnable thread runs next \cite{man7}. Threads of one process share data and heap but have their own stacks \cite{man7}. & For a slow multithreaded service, look at runnable threads and scheduling next to latency, and tell waiting in the ready queue from waiting for an event. For a restart, read the process logs and signals before naming a cause. \\
\hline
Virtual memory & Page tables translate virtual to physical addresses \cite{kernel-docs}. A major page fault needs I/O \cite{manpages-debian-testing-manpages-dev-getrusage-2-en-html}, and direct reclaim can stall an allocation \cite{kernel-docs}. & Compare a service's virtual mappings with its resident memory. Read changes in major-fault counts as evidence, not as proof of exhaustion. \\
\hline
File systems and I/O & A successful \texttt{write()} does not mean the data is on disk \cite{man7}. \texttt{fsync()} waits until the device reports completion \cite{man7}. & For a service that writes persistent data, separate successful writes, cache activity and completed synchronization when investigating latency or crash recovery. \\
\hline
Networking and permissions & Sockets connect processes to the kernel network stack, TCP retransmits lost packets, and missing directory search permission gives EACCES \cite{man7}. & For a slow or failed connection, check its socket and TCP behavior. For a file-access failure, check directory permissions before widening them. \\
\hline
Containers, virtualization and resource control & Namespaces implement containers \cite{man7}. Cgroups distribute resources \cite{kernel-docs}. Containers share one kernel \cite{docs-docker-get-started-docker-concepts-the-basics-what-is-a-container}. Kubernetes enforces CPU limits by throttling and memory limits by out-of-memory kills \cite{kubernetes-docs}. QEMU supplies a virtual machine with its own guest OS \cite{qemu-docs-master-system-introduction-html}. & Compare the guest OS and virtual hardware of a virtual machine with the shared kernel of containers, and separate namespace isolation from cgroup resource control. \\
\hline
Failure detection and recovery & Kubernetes can restart unhealthy containers or stop traffic to containers that are not ready \cite{kubernetes-docs}. The SRE book recommends limiting retries per request \cite{sre-book}. & Separate an observed failed check from a confirmed root cause, and test bounded retries before assuming they restore availability. \\
\hline
\end{longtable}

\paragraph{A recommended chain.}
In the form of the assignment's examples, our recommended chain is: SRE, then a hypothetical containerized web service, then Linux, then a server or virtual machine that provides CPU, RAM, storage and network, then Docker containers managed by Kubernetes, then processes, scheduling, virtual memory, file I/O, networking, permissions and resource isolation. This is an example for study and not a verified description of Google's infrastructure.
